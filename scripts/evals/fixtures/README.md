# Eval fixtures

Sample inputs + ground truth for the MECHA eval sandbox (`scripts/evals/`).
Drop the actual sample files in THIS directory (`scripts/evals/fixtures/`)
next to this README. Fixtures are test data only — never customer data, never
real user uploads. Record voice notes and take photos yourself (or use
synthetic / freely licensed samples) so nothing private is ever committed.

## What to drop in

### Voice notes — transcription fixtures (target: 3 files)

Short spoken car-problem descriptions, 10–45 seconds each, recorded the way a
MECHA customer would actually send them (phone mic, car/street noise is fine —
realistic noise is the point).

| File | Content |
| --- | --- |
| `voice-01-brakes-en.mp3` | English: grinding/squealing brakes, when it happens (e.g. "grinding noise when I brake, started yesterday, worse at low speed"). |
| `voice-02-start-en.wav` | English: starting problem (e.g. "clicks once and won't start, dashboard lights come on, battery is two years old"). |
| `voice-03-nonenglish.m4a` | **Non-English** (Spanish is ideal for MECHA's market — e.g. a spoken description of an overheating engine / steam / temperature light). Tests multilingual transcription, where open Whisper models should be strongest. |

Any common format works (`.mp3`, `.wav`, `.m4a`, `.ogg`, `.flac`, `.webm`) —
both transcription scripts detect the type from the extension.

### Dashboard photos — vision fixtures (target: 3–5 files)

Phone photos of an instrument cluster / dashboard, again realistic: mixed
lighting, slight blur or glare is good — that's what customers send.

| File | Must show (ground truth) |
| --- | --- |
| `dash-01-check-engine.jpg` | Check-engine (malfunction indicator) light illuminated, engine running. |
| `dash-02-oil-battery.jpg` | Oil-pressure light + battery/charging light illuminated (key-on, engine-off cluster sweep is fine). |
| `dash-03-abs-tpms.jpg` | ABS light + tire-pressure (TPMS) light illuminated. |
| `dash-04-none.jpg` | **Negative control:** cluster with NO warning lights illuminated. A model that invents lights here fails this fixture outright. |
| `dash-05-coolant.jpg` (optional) | Coolant-temperature light illuminated. |

## Ground truth — `fixtures/ground-truth.json`

Create `fixtures/ground-truth.json` in this directory. One entry per fixture
file. Schema:

```jsonc
{
  "fixtures": [
    {
      "file": "string — fixture filename, exactly as saved in this directory",
      "type": "\"audio\" | \"image\"",
      // audio fixtures only:
      "language": "string — ISO 639-1 code of the spoken language, e.g. \"en\", \"es\"",
      "expected_transcript": "string — the words actually spoken, transcribed by a human, verbatim",
      "key_facts": ["string — facts a useful transcript must preserve (symptom, part, timing)"],
      // image fixtures only:
      "expected_lights": [
        {
          "name": "string — canonical light name, e.g. \"check engine\"",
          "explanation": "string — one plain sentence a driver would understand"
        }
      ],
      "notes": "string — optional: lighting/blur caveats, key-on vs engine-running, etc."
    }
  ]
}
```

Rules:

- `expected_transcript` is written by a human listening to the recording —
  never generated by one of the models being evaluated.
- `expected_lights` lists ONLY lights actually illuminated in the photo.
  For the negative-control photo, use `"expected_lights": []`.
- Fill in ground truth BEFORE running any model, and don't edit it after
  seeing results — that's what makes the comparison honest.

### One fully filled example

```json
{
  "fixtures": [
    {
      "file": "voice-01-brakes-en.mp3",
      "type": "audio",
      "language": "en",
      "expected_transcript": "Hi, my car makes a grinding noise every time I press the brakes. It started yesterday and it is worse when I am going slow. The car still stops fine but the noise is getting louder.",
      "key_facts": ["grinding noise", "when braking", "started yesterday", "worse at low speed", "car still stops"],
      "notes": "Recorded in a parked car with the window down; mild street noise."
    },
    {
      "file": "dash-01-check-engine.jpg",
      "type": "image",
      "expected_lights": [
        {
          "name": "check engine",
          "explanation": "The engine or emissions system has a fault and the car should be scanned for trouble codes soon."
        }
      ],
      "notes": "Engine running, daylight, slight glare on the cluster glass."
    },
    {
      "file": "dash-04-none.jpg",
      "type": "image",
      "expected_lights": [],
      "notes": "Negative control: engine running, all warning lights off."
    }
  ]
}
```

(Your real file should have one entry for EVERY fixture — 3 audio + 3–5
image entries.)

## Scoring sheet format

One row per fixture per system under test. Score accuracy by comparing the
system output against `ground-truth.json` — by a human, using the rubric
below. Record latency and cost exactly as each script prints them
(`latency_ms`, cost note / usage / `predict_time`).

| fixture | system | accuracy (0–2) | latency_ms | cost | notes |
| --- | --- | --- | --- | --- | --- |
| voice-01-brakes-en.mp3 | claude-current | | | | |
| voice-01-brakes-en.mp3 | hf-whisper-large-v3 | | | | |
| voice-01-brakes-en.mp3 | replicate-whisper | | | | |
| dash-01-check-engine.jpg | claude-vision-current | | | | |
| dash-01-check-engine.jpg | hf-qwen2.5-vl-7b | | | | |
| dash-01-check-engine.jpg | replicate-vision | | | | |

System names: `claude-current` / `claude-vision-current` = the current
production stack (triage `claude-haiku-4-5` class via Anthropic/OpenRouter;
dashboard photos via the Anthropic vision provider). Trial names as in the
table above; if you override a model id via env, write the actual model id
used, not the default label.

### Accuracy rubric (0–2 per fixture)

**Audio (transcription):**

- **2** — Transcript preserves every key fact and is directly usable as the
  customer's problem description (minor word errors OK if meaning is intact).
- **1** — Main problem is understandable but a key fact is missing/wrong
  (wrong part, wrong symptom, dropped timing), or heavy errors force a
  re-listen.
- **0** — Wrong language, garbled, hallucinates a different problem, or
  unusable.

**Image (warning lights):**

- **2** — Every illuminated light correctly identified, no invented lights,
  each explanation plain and correct.
- **1** — Most lights right but one missed, misnamed, or a vague/wrong
  explanation.
- **0** — Misses the main light, invents lights that are not on (automatic 0
  on the `dash-04-none.jpg` negative control), or describes a different photo.

### Comparing

- Total accuracy per system = sum over fixtures (report audio and image
  subtotals separately — the two capabilities are decided separately).
- Latency = median `latency_ms` per system per fixture type (cold-start
  outliers noted, not silently dropped).
- Cost = per-run cost note from each script; for the Claude stack use the
  API usage (tokens) from the production provider response for the same input.
- Decision rule: see `../README.md` — a trial replaces nothing until it
  ties-or-beats the current stack on accuracy at lower cost.
